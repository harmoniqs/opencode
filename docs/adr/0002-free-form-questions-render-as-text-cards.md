# Free-form questions render as text cards

Status: accepted (2026-08-02)

Tracking: harmoniqs/amicode#245 · Glossary: `CONTEXT.md` (Question, Choice Question, Free-form Question, Text card)

The question tool's schema grows an optional `kind` (`choice` default, `text`) on both the agent-facing and server question shapes. A **Free-form Question** — an ask expecting an open-ended typed answer (a name, a number, "in your own words") — renders as a **Text card**: the header, a bare text input, and submit, with no option list and no typed-custom-answer pseudo-option, in the app dock, the TUI, and the CLI alike. The interview contract (the extension's compiled contract plus the overture and pulse-designer score bodies) teaches the model to use it for every free-form ask, uniformly across Amico interviews. The prose guard's behavior is unchanged — prose questions in active interviews are still forced into cards — but its nudge text becomes bilingual: choice questions re-ask with options (recommended first); free-form questions re-ask with the text kind. Text-card answers resolve through the existing typed-custom-answer path, and submit requires non-empty trimmed text. Choice cards are unchanged, save the app dock now honoring the typed-custom-answer flag it previously ignored.

**Why:** since PR #37 the session turn loop forces every prose question in an active interview into a card, closing the interview-stall class (a prose question renders nothing to answer). But the card's only text path is the typed-custom-answer pseudo-option appended to an option list — so a free-form ask (the overture's name question, harmoniqs/amicode#245) could only ever render as a choice card: fabricated options, or a one-row list whose lone row is "Type your own answer." Every free-form interview ask inherits that rendering. The fix gives the free-form ask a first-class card shape instead of carving prose back out of the guard.

**Accepted costs:** the schema field ships in the vendored engine pin, so reversing it means a new pin plus model-facing contract whiplash. Three renderers must each keep the text-card branch honest across upstream syncs — the app dock's question component is already a high-conflict file there. The guard's nudge now instructs two shapes and trusts the model to pick from the question it is re-asking, rather than classifying in the loop (a deliberate choice: loop-side classification of prose intent is brittle).

**Considered:** prose carve-out for free-form questions (runner-up: zero schema surface, but re-admits the PR #37 stall class for exactly the questions onboarding depends on, and prose answers bypass the question-answer plumbing) · implicit empty-options-means-text (rejected: no legible way for the model to ask for it, and any renderer change can silently break the signal) · wizard-only identity collection (rejected for #245: fixes the name step only and couples the chat flow to a dismissable modal; every other free-form ask stays broken) · exposing the server-side custom-answer flag to the agent schema (rejected: more surface than the kind field for the same outcome).

**Flip condition:** if the question tool ever grows a general rich-form surface (mixed input types within one question), revisit whether free-form text becomes a field type within it rather than a question kind.
